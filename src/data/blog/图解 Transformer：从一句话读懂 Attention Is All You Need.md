> 小猫趴在垫子上，因为它累了。

读到“它”，你会想到小猫。因为会累的是猫，前半句也交代了小猫正趴着休息。

如果让电脑翻译这句话，它也需要把相隔几个词的“小猫”和“它”联系起来。只查出每个词的英文，还不足以完成翻译。

2017 年的论文 [《Attention Is All You Need》](https://arxiv.org/abs/1706.03762)提出了 Transformer。它是一种模型结构，规定了电脑怎样处理输入、联系上下文、生成输出。原论文主要用机器翻译来检验这套方法。

我们就从“小猫趴在垫子上，因为它累了”这个例子出发，看看联系上下文这件事，怎样变成电脑能做的计算。文中的配图、分词和算例均为教学示意；实际计算的细节放在可展开的补充说明里。

## 先看“它”，为什么需要前后文

把句尾的“累了”换成“太软了”：

> 小猫趴在垫子上，因为它太软了。

这次，“它”更可能指垫子。“软”描述的是垫子的质地，也解释了猫为什么愿意趴在上面。

![句尾是“累了”时，“它”更可能指小猫；换成“太软了”时，“它”更可能指垫子。同一个代词，需要结合前后文理解。](@/assets/images/posts/attention-is-all-you-need-explained/01_context.png)

对人来说，这个判断很自然。对模型来说，需要有一种办法，让处理“它”的计算用上“小猫”“垫子”“累了”等词的信息。

**注意力**（Attention）就提供了这样的办法：计算一个词时，先判断其他词能提供多少参考，再按不同的比例汇集它们的信息。关系较强的词，提供的信息通常会占更大比例。

这里先借用人读句子的过程帮助理解。模型实际做的是数字运算，注意力大小也不等于“它指代谁”的判断概率。

## “自注意力”就是在同一句话里找线索

把“小猫趴在垫子上，因为它累了”按词语拆开：

> 小猫 / 趴在 / 垫子上 / 因为 / 它 / 累了

如果正在理解“它”，可以参考“小猫”和“累了”；如果正在理解“趴在”，则可以参考“小猫”和“垫子上”，弄清谁趴在哪里。

![同一句话中，理解“它”可以参考“小猫”和“累了”，理解“趴在”可以参考“小猫”和“垫子上”。处理的词和提供线索的词都来自这句话。](@/assets/images/posts/attention-is-all-you-need-explained/02_self_attention.png)

**处理的词来自这句话，找线索的范围也在这句话里面**，这种注意力就叫自注意力（Self-Attention）。这里的“自”指的是输入自身的内容。本文用一句话作输入；如果输入是一段文字，找线索的范围也可以扩展到整段。

所以，“自注意力”允许“它”参考“小猫”，也允许“趴在”参考“垫子上”。每个词还可以保留来自自己的信息。实际计算时，会对所有允许参考的词算出比例，图里只挑了几条容易理解的关系。

经过一轮计算，“它”对应的信息就不再只有这个字本身，还混入了这句话的上下文。这是自注意力在模型里承担的工作。[原论文 §3.2.3](https://arxiv.org/pdf/1706.03762)

## 电脑怎么保存一个词的信息

电脑不能直接拿“小猫”两个字做乘法，需要先把文字换成数字。

可以想象给每个文字片段发一张“数字卡片”。卡片上写着一排数，例如 `[0.2, 0.8, 0.1]`。这一排数就叫**向量**。文章后面说“词的信息”，在模型里指的就是这样的数字。

文字片段的正式名字是 **token**。一个 token 可能是一个字、一个词，也可能只是单词的一部分。本文为了便于阅读，暂时按完整词语画图。

![“我、喜欢、小猫”各自有一张数字卡片，模型再把位置对应的数字加进去。调换词序后，词语与位置的搭配发生变化。](@/assets/images/posts/attention-is-all-you-need-explained/03_embedding_position.png)

把 token 换成数字卡片，叫 **Embedding**，通常译为“嵌入”。卡片里的数会在训练中调整：模型反复做翻译练习，根据预测与正确答案的差距改进这些数字。它们通常没有“第一格表示动物、第二格表示可爱”这样由人规定的含义。

还有一个容易漏掉的问题：**顺序也会改变意思**。

- 我喜欢小猫。
- 小猫喜欢我。

两句话用的是相同的词，但谁喜欢谁变了。模型需要知道每个词排在第几位，因此会把一组与位置有关的数字加到词的卡片上。这组数字叫**位置编码**。原论文用正弦、余弦函数生成它，暂时记住它用来提供词序信息就够了。[原论文 §3.4、§3.5](https://arxiv.org/pdf/1706.03762)

## 用查书理解 Q、K、V

假设你去图书馆查“猫为什么爱睡觉”。你会先看书名、目录，判断哪些书相关，再翻到正文找资料。

这个过程里有三样东西：你的查询问题、用来判断相关性的书目线索、书里实际提供的内容。注意力计算中的 Q、K、V，可以先借这三样东西来记。

![查书的类比：Q 是想查的问题，K 是供比较的书名或目录，V 是书里实际提供的内容。先用 Q 与 K 判断相关程度，再从对应的 V 取信息。](@/assets/images/posts/attention-is-all-you-need-explained/04_qkv.png)

| 字母           | 查书时对应什么         | 在注意力计算中做什么         |
| -------------- | ---------------------- | ---------------------------- |
| Q，Query，查询 | 我想查“猫为什么爱睡觉” | 表达当前要找什么信息         |
| K，Key，键     | 书名、目录等检索线索   | 与 Q 比较，计算匹配程度      |
| V，Value，值   | 书里的正文内容         | 按匹配后得到的比例，提供信息 |

为什么把 K 和 V 分开？因为**用来判断相关性的线索，和最后要取用的内容，承担不同的工作**。目录帮助你找到章节，真正有用的解释在正文里。

带回小猫的例子：处理“它”时，模型拿“它”的 Q，与“小猫”“累了”等词的 K 比较；得到各自的参考比例以后，再按这些比例汇集对应的 V。

实际模型没有书名、目录，也不会先写出一个中文问题。它把每个词的数字卡片分别加工三次，产生 Q、K、V 三张新卡片。三套加工规则都由训练学出来。同一个词因此既能用自己的 Q 找线索，也能拿自己的 K、V 给别的词提供线索。

## “按比例汇集信息”，到底怎么算

仍然处理“它”。为了把计算看清楚，我们只保留三个可参考的词，假设匹配计算后得到的比例是：小猫 60%，累了 30%，垫子 10%。

这个比例叫**注意力权重**。60% 表示“小猫提供的信息，在这次汇集中占六成”，并不表示有 60% 的把握认定“它”就是小猫。

![简化算例：小猫、累了、垫子分别提供向量 [2,0]、[0,2]、[1,1]；按 60%、30%、10% 混合，逐格相加得到 [1.3,0.7]。](@/assets/images/posts/attention-is-all-you-need-explained/05_weighted_sum.png)

图里每张 V 卡片只有两个数。计算时，两格分开算：

```text
第一格：2 × 0.6 + 0 × 0.3 + 1 × 0.1 = 1.3
第二格：0 × 0.6 + 2 × 0.3 + 1 × 0.1 = 0.7

汇集结果：[1.3, 0.7]
```

这就是**加权求和**。“加权”是先乘上比例，“求和”是再把结果加起来。输出仍然是一张数字卡片，只是现在包含了其他词提供的信息。

那 60%、30%、10% 从哪里来？模型会用 Q 和每个 K 算匹配分数，再通过一个叫 **softmax** 的计算，把分数变成总和为 100% 的比例。同一组分数里，分数越高，得到的比例越大。这里直接假设比例，是为了只看清最后的汇集过程。

<details>
<summary>想把这几个动作与论文公式对上，可以展开看</summary>

`Attention(Q, K, V) = softmax(QKᵀ / √dₖ)V`

可以把它读成“算匹配分数 → 缩放分数 → 换成比例 → 汇集内容”。

- `QKᵀ` 一次算出许多组匹配分数。单独一组是把 Q、K 对应的数字相乘后相加，叫点积。
- `dₖ` 是一张 Q 或 K 卡片里有多少个数。除以它的平方根，可以控制分数的大小，让训练更稳定。
- `softmax` 把每组分数变成非负、总和为 1 的权重；它不是简单地把分数除以总分。
- 最后乘 V，就是图中的加权求和。

公式使用矩阵来批量处理许多词。矩阵可以先理解成把多张数字卡片排列成的一张表。[原论文 §3.2.1、公式（1）](https://arxiv.org/pdf/1706.03762)

</details>

## 多头和多层，分别多在哪里

一句话里有许多关系。“它”可能需要联系“小猫”，“趴在”还涉及动作和地点。只用一套匹配方法，未必能同时照顾好这些关系。

模型可以并排运行几组注意力计算。每组都有自己的 Q、K、V 加工规则，会得到自己的参考比例和汇集结果。这样的一组计算，就叫一个**注意力头**。

![三组注意力同时处理同一份输入，各自计算参考比例、汇集信息，再把结果拼接和加工，形成这一轮的输出。不同的头可以学到不同关系。](@/assets/images/posts/attention-is-all-you-need-explained/06_multihead.png)

你可以把它想成几个读者各自做笔记，再把笔记合在一起。但模型里不会提前指定“第一个头找主语、第二个头找地点”。不同头关注什么，是训练出来的，也可能出现重复。

论文基础模型用了 8 个头，图里只画了 3 个。各头的结果会拼接起来，再经过一次数字变换，形成合并后的结果。[原论文 §3.2.2](https://arxiv.org/pdf/1706.03762)

**多层则是把这样的处理继续做几轮**。第一轮得到的数字卡片，交给下一轮继续处理。好比读完一遍做了笔记，再带着笔记重读，继续补充信息。

因此，多头说的是“一轮里有几组计算”，多层说的是“前后接着做几轮”。

## 从一句话里的线索，到一整句译文

现在把任务缩短一点：把“小猫睡了”翻译成 `The cat slept`。

原版 Transformer 分成两部分。**编码器**读取中文，把每个 token 的数字卡片加工成带有上下文的信息；**解码器**参考这些信息和已经写出的英文，预测下一个英文 token。

![编码器把“小猫睡了”加工成一组原文信息。解码器同时参考原文信息和已生成的“The”，预测下一个词“cat”，再把新词接回译文继续预测。](@/assets/images/posts/attention-is-all-you-need-explained/07_translation.png)

比如英文已经写出 `The`，接下来写什么？解码器要参考两边：

| 参考什么                       | 为什么需要它             | 对应的计算     |
| ------------------------------ | ------------------------ | -------------- |
| 已有英文 `The`                 | 让后续词语能接上已有译文 | 解码器自注意力 |
| 中文原文“小猫睡了”加工后的信息 | 确定要表达的内容         | 交叉注意力     |

**交叉注意力**（Cross-Attention）这个名字，现在就容易理解了：写英文时，去参考中文原文的信息。查询来自解码器，提供线索和内容的 K、V 来自编码器。自注意力则是在同一份输入内部互相参考。[原论文 §3.2.3](https://arxiv.org/pdf/1706.03762)

解码器最终会给词表里的候选 token 分配概率，比如 `cat`、`dog`、`bird` 各占多少。生成过程根据这些概率选择后续 token，选出 `cat` 后，已有译文就变成了 `The cat`，再继续预测。

<summary>回到论文图 1：还有哪些零件没有展开讲？</summary>

前面的流程图只保留了读原文、参考原文、续写译文三件事。论文图 1 还画出了每一层的内部结构。

| 图中的名字             | 可以怎样理解                                                                             |
| ---------------------- | ---------------------------------------------------------------------------------------- |

| Add，残差连接          | 把子层原先的输入加回处理结果，让原有信息也有直接传下去的通道                             |
| Norm，层归一化         | 按每个 token 的向量调整数值的尺度，帮助训练                                              |

## 学翻译的时候，怎样防止偷看答案

让模型练习 `The cat slept`，可以把题目排成这样：

| 已知内容                     | 要预测的下一项 |
| ---------------------------- | -------------- |
| 起始标记                     | The            |
| 起始标记 + The               | cat            |
| 起始标记 + The + cat         | slept          |
| 起始标记 + The + cat + slept | 结束标记       |

“起始”和“结束”是告诉模型何时开始、何时结束的特殊 token。每道题都能参考完整的中文原文“小猫睡了”。

假如模型在第二道题直接看到了 `cat`，就变成了照抄答案。因此，要在计算里挡住尚未写出的英文。这种限制叫**因果遮罩**（Causal Mask）。

![绿色格子表示可以参考的输入，灰色格子表示被遮住的未来输入。预测 cat 的那一行，只有起始标记和 The 可以看。](@/assets/images/posts/attention-is-all-you-need-explained/08_causal_mask.png)

看图的第二行：输入停在 `The`，要预测的是 `cat`。`The` 可以参考自己和前面的起始标记，但后面的 `cat`、`slept` 都被挡住了。这也是为什么输入与答案要错开一格。

**训练时，完整的正确译文是已知的**。所以可以一次摆出所有练习题，用遮罩保证每道题只能看到自己的已知内容，然后同时计算各题的预测。

![训练时，正确译文被拆成多道带遮罩的填空题，可以一起计算。生成时，没有标准译文，必须把刚生成的词接回已有译文，再算下一词。](@/assets/images/posts/attention-is-all-you-need-explained/09_train_generate.png)

如果正确答案是 `cat`，模型却给 `dog` 更高的概率，训练程序就会根据预测误差调整参数。词的数字卡片、Q/K/V 的加工规则，以及其他计算部件，都会在大量这样的练习中逐渐调整。

**真正翻译新句子时，手里没有标准英文答案**。模型只能先生成 `The`，把它接回输入，再生成 `cat`，接着生成 `slept`，直到结束。因此，训练能同时练习多个位置，生成译文仍需要一步步往后写。[原论文 §3.1、§3.2.3](https://arxiv.org/pdf/1706.03762)、[TensorFlow 官方翻译教程](https://www.tensorflow.org/text/tutorials/transformer)

## 再回头看，论文改进了什么

理解了这套过程，再看 Transformer 之前常用的**循环神经网络**（RNN），差别会更明显。

RNN 处理一句话时，会把前一步算出的中间记录交给后一步。像接力一样，后面的计算要等待前面的记录。若想把句首的信息传到很后面的词，这条状态传递链也会很长。

![RNN 的中间记录沿着词序逐步传递；自注意力让各词同时参考上一轮已有的全部数字卡片，减少同一层内按词序等待的计算。](@/assets/images/posts/attention-is-all-you-need-explained/10_parallel.png)

Transformer 中，同一层的各个词可以直接参考上一层已经算好的信息，同时完成各自的注意力计算。相隔很远的词也能建立直接联系。计算设备擅长同时处理许多数字，这样的安排更适合它们发挥能力。层与层之间仍有先后关系。[Google 研究团队的原始介绍](https://research.google/blog/transformer-a-novel-neural-network-architecture-for-language-understanding/)

注意力机制在这篇论文之前就存在，也被用在翻译模型里。Transformer 的贡献，是用注意力承担序列中词与词的信息交流，构建出不依赖循环和卷积的翻译模型。标题里的“All You Need”要结合这个背景理解，整个模型依然包含前馈网络、位置编码等部件。

这种直接联系也有代价。普通的全局自注意力要计算词与词两两之间的匹配分数：100 个 token 需要 10,000 个分数，200 个就需要 40,000 个。因此，文本很长时，这部分计算和存储会明显增加。[原论文 §1、§4、表 1](https://arxiv.org/pdf/1706.03762)

原论文在 WMT 2014 英译德测试中报告了 28.4 BLEU。BLEU 是比较机器译文与参考译文的一种分数，不能把它当成“正确率 28.4%”。论文的重要结果，是这套新的组织方式在当时的翻译测试中兼顾了质量与训练效率。[原论文摘要、表 2](https://arxiv.org/pdf/1706.03762)

开头那句“小猫趴在垫子上，因为它累了”，现在可以按模型的处理过程再读一次：每个词先有一张数字卡片；处理“它”时，从同一句话里汇集线索；经过几组、几轮计算，形成带上下文的信息；翻译时，解码器参考这些信息，逐步写出英文。

这些计算提供了利用上下文的方法。模型能否在某句话里正确理解指代，还取决于训练学到了什么，不能只凭某条注意力连线就下结论。

- [Transformer: A Novel Neural Network Architecture for Language Understanding，Google Research](https://research.google/blog/transformer-a-novel-neural-network-architecture-for-language-understanding/)：论文作者之一 Jakob Uszkoreit 写的介绍，解释了研究动机和词与词如何联系。
- [Neural machine translation with a Transformer and Keras，TensorFlow](https://www.tensorflow.org/text/tutorials/transformer)：有编码器、解码器和训练过程的完整示例，适合想继续看代码的读者。
